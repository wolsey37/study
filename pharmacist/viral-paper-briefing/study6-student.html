  • 초록 — 논문 맨 앞의 요약문. 이 도구는 본문이 아니라 초록만 읽습니다 · PMID — PubMed 논문 번호
  • 메타분석 — 여러 연구를 모아 다시 분석한 연구 · RCT — 무작위로 나눠 비교한 임상시험
  • MeSH — 미국 국립의학도서관이 논문마다 붙인 주제 태그. 검색을 정확하게 해 줍니다
  • 신뢰구간 — 효과 숫자의 오차 범위. 「25% 감소(95% 신뢰구간 10~38%)」처럼 붙습니다
  • 키 — 외부 서비스(PubMed·네이버·식약처)에 접속할 때 쓰는 개인 비밀번호 같은 값. 남에게 보이면 안 됩니다
  • 주제와 무관한 논문(off-target) — 검색에는 걸렸지만 다른 물질·다른 이야기라서 걸러낸 논문. 진행 줄에 「off-target N편」으로 나옵니다
  • 후킹 문구 — 영상 첫 3초에 시선을 붙잡는 첫 문장 · 방어 소재 — 부작용·효과 없음 논문. 「용량 보고 드세요」 식 복약지도에 씁니다

둘 — NCBI API 키를 넣습니다 (오늘은 꼭 넣습니다)

PubMed를 키 없이 쓰면 초당 3회 제한입니다. 이 제한은 인터넷 연결(IP) 단위라, 강의장처럼 여러 명이 같은 와이파이로 돌리면 서로 막힙니다. 키가 있으면 사람마다 초당 10회가 됩니다. 무료이고 1분이면 발급됩니다.

  1. ncbi.nlm.nih.gov/account 로그인
  2. Account Settings → API Key Management → Create an API Key

키를 넣습니다

.claude/settings.local.json 의 NCBI_API_KEY 빈 칸에 "발급받은키" 를 넣어줘.

왜 검색 담당은 숫자를 넘기지 않게 했나

검증되지 않은 숫자가 새어 나가는 통로가 되기 때문입니다. 검색 담당도 초록을 읽고 방향·대상자를 판정하지만, 초록 문장과 숫자는 결과 파일에 넣지 않습니다. 숫자는 채점 단계에서만 뽑고, 그 숫자는 전부 대조를 거칩니다.

프로그램이 필요한 이유 — 실제로 났던 사고

사고 1

「반드시 옮겨라」라고 적었는데 안 옮겼습니다

채점 담당 설명서에 「방향 값을 반드시 그대로 옮겨라」라고 적어 뒀습니다. 그런데 실제 결과 파일에는 그 항목이 통째로 없었습니다. 다음 단계는 그 사실을 모른 채, 초록을 다시 읽고 스스로 재판정했습니다. 원래 mixed였던 논문이 최종 브리핑에서 negative로 바뀌어 있었습니다.

설명서에 적는 것과 실제로 지켜지는 것은 다른 문제입니다. 프로그램이 검사해서, 빠져 있으면 다음 단계로 못 갑니다.

사고 2

요약 숫자를 원고 담당 AI가 직접 세고 있었습니다

브리핑 맨 위 요약표에 「근거약함 없음 8편」이라고 적혀 있었는데 실제로는 12편이었습니다. 27편을 눈으로 세다 어긋난 것입니다. 스무 개가 넘으면 AI도 셈이 틀립니다.

프로그램이 정확히 세어 파일에 넣어 두고, 브리핑을 만들 때 그 숫자와 대조합니다. 어긋나면 멈춥니다.

오늘 한 것

고친 파일은 하나입니다. 계정 프로필 (계정/프로필.md). 사전도 AI 담당도 프로그램도 들어 있는 그대로 썼습니다.

한 흐름을 돌렸습니다. 프로필을 고치고, /브리핑 한 줄로 주제를 골라 돌리고, 결과를 점수 세 개와 경고로 읽고, 쓸 논문을 기록했습니다. 그 사이 숫자는 전부 초록 원문과 대조를 거쳤고, 결과는 초록 기준이라 쓸 논문은 본문을 직접 확인해야 한다는 것도 봤습니다.

사람이 고르는 자리는 두 군데였습니다 (제품명으로 넣으면 제품까지 세 군데). 어떤 주제로 볼지 고르는 자리, 그리고 나온 브리핑에서 무엇을 콘텐츠로 만들지 고르는 자리. 그 사이는 전부 위임했습니다.

트렌드 점수는 실제로 잰 값이지만 「찾는 사람이 많다」까지만 알려 줍니다. 콘텐츠 적합도는 규칙대로 매긴 점수이지, 반응으로 검증된 배점이 아닙니다. 발행 후 반응이 점수와 다르면 배점표를 고쳐 가며 맞추십시오. 배점표는 .claude/agents/p4-content-scorer.md 에 한국어로 적혀 있고, 바꿀 때는 검사 프로그램(scripts/validate_schema.py)의 표도 함께 고쳐 달라고 하십시오.
